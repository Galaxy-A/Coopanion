# HeyBox Voice World

The `heybox` World receives audio from the HeyBox process tree, recognizes it locally and sends `heybox.speech` to Core. Replies use the existing GPT-SoVITS HTTP service. The free microphone route mixes replies into your existing microphone with Equalizer APO; an explicit output-device route remains available for virtual cables. Your HeyBox speakers can remain on headphones or the current output.

Core uses `heybox_say` for room replies, combining GPT-SoVITS synthesis and HeyBox sending in one call. Local desktop conversations keep using `sovits_speak`; starting the bridge does not broadcast all local conversations to the room. Core decides whether to reply using room context and address cues.

Requires Windows build 20348 or later, x64 for the microphone plugin and guided installers, Node.js 22+, the GPT-SoVITS World and this checkout's `cortico-world-desktop-pet/asr` library export. This export supplies recognition primitives without calling or changing the desktop-pet World. The product runtime installer deploys it with the desktop-pet package. An older desktop-pet 0.2.0 package without this export must be upgraded with the product before enabling this extension.

Install this package from its local directory on the extension page, restart Core and enable the `heybox` World. The package includes its own x64 microphone-plugin DLL and source. Built-in Windows PowerShell compiles the C# helpers at launch; users need no compiler. It bundles no third-party installer, driver, audio or model weights.

## First use

1. Open the World panel and click **Configure HeyBox voice**. It checks the speech service, Windows version, audio devices, recognition model and running HeyBox processes. A new configuration suggests the default microphone. Existing explicit output-device configurations are retained; select **Current microphone (free component)** to change routes.
2. Choose the same physical microphone used in HeyBox. Click **Install Equalizer APO (free)** if needed. The official installer is downloaded into the current data directory, then lets you choose its installation location. The extension does not assume a fixed path; after installation it follows the actual `InstallPath` and `ConfigPath` reported by Windows. No Soundpad purchase or separate mixer is needed.
3. Click **Enable microphone audio mixing**. Administrator approval installs this package's plugin into a protected directory and adds a managed Include to Equalizer APO without replacing your other settings. In the official device selector, enable the same microphone under recording devices. Follow its restart instructions, keep microphone audio enhancements enabled in Windows and reopen HeyBox voice. The panel reports readiness only when plugin audio callbacks are advancing. If processing stays inactive, check the selector and open HeyBox's microphone test. HeyBox must keep using this same microphone.
4. Enable the GPT-SoVITS World's HTTP API, normally on `http://127.0.0.1:9880`. If it uses a token, store the same value as the deployment secret `HEYBOX_TTS_TOKEN`. This extension accepts only loopback HTTP(S) addresses and sends `Authorization: Bearer` when configured.
5. Download the recognition model if requested (about 240 MB). Existing desktop-pet SenseVoice model files are reused from the shared model cache. Microphone capture and desktop-pet recognition settings are unchanged.
6. Play a short phrase and ask a room participant to confirm they heard it. Then click **Friend confirmed hearing it** beside playback. Click **Check reception** in the top action bar, ask them to speak and wait for a transcript in the reception area below it. This area shows whether reception has started or is waiting for audio. Reception checks show text without sending it to Core. Leaving the panel stops check capture.
7. Click **Start bridge** after both checks are complete. Later sessions need only this button. The checks persist across app restarts, while capture always starts stopped. Stop bridge releases capture and stops current and queued speech. Refresh configuration after changing devices or restarting HeyBox. If several HeyBox root processes exist, select one explicitly.

The microphone route is `GPT-SoVITS HTTP → World plugin + original microphone audio → HeyBox microphone`. It affects the endpoint: other applications recording that microphone can also receive synthesized speech. Use headphones to avoid acoustic feedback, and hold HeyBox's talk key during sending if push-to-talk is enabled. Stopping speech or the bridge leaves microphone input intact. **Remove audio mixing configuration** removes this World's Include and plugin configuration; it does not uninstall Equalizer APO or remove other effects.

### Explicit output-device route

Choose **Virtual cable / output device** to keep or use an existing route. A unique `CABLE Input` can be selected when configuring this mode. If missing, **Download and install VB-CABLE** downloads the official archive, verifies the installer signature and requests administrator installation. Restart Windows, then select **CABLE Output (VB-Audio Virtual Cable)** as HeyBox's microphone. The route is `GPT-SoVITS HTTP → selected CABLE Input playback → CABLE Output recording → HeyBox microphone`. This mode sends synthesized speech only; it does not mix in your physical microphone. Installer files remain under `<CORTICO_HOME>/drivers/vb-cable`. Try synthesized speech with automatic gain, echo cancellation and noise reduction off, adjusting as needed.

Receiving uses Windows process loopback, including children of `HeyboxChat.exe`. It needs no virtual cable and does not change system audio defaults. Missing or ambiguous selections fail explicitly. The World never switches sending modes automatically on an error, and capture never falls back to system mix or the default microphone. Send confirmation is tied to the selected route and must be completed again after changing it.

Enter any name or phrase in **Address keyword** below the reception transcript and click **Save keyword**. It takes effect immediately and survives app restarts. The latest transcript shows whether it contains the saved keyword, including during reception checks. Matching uses literal substrings, ignores case and Unicode compatibility differences, and trims surrounding keyword whitespace. Leave it blank to disable the cue. This setting applies to this World's process-audio transcripts.

## Runtime contract

- `heybox_say({"text":"Hello, everyone."})` works while the bridge is running. It accepts 1–2000 characters, queues at most eight utterances and returns after the microphone processing stream consumes the audio or the output device finishes playback. Room confirmation is a separate operator assertion.
- `heybox_hush({})` cancels HTTP waits, stops synthesized speech and clears the queue without closing the physical microphone. The server may continue inference after client disconnection.
- `heybox_status({})` refreshes service, devices and processes and reports capture, recognition and setup state.
- `heybox.speech` contains recognized process audio as external content, with no authenticated speaker identity. Multiple participants, music and app sounds can share the same stream. Every body starts with `[heybox.speech] HeyBox voice room | reply audio: heybox_say`, identifying its source and reply route. The original transcript follows `Transcript` and is retained in the `transcript` metadata. Events use `flush` and do not interrupt Core.
- With `addressKeyword` configured, a JSON `HeyBox address cue` (`keyword`, `matched`) appears between the source marker and transcript. Metadata also includes `addressKeyword` and `addressKeywordMatched`. A match gives Core a possible address cue; Core decides whether to reply. Unmatched speech is still delivered. The default empty keyword adds no address cue.

Output names use exact unique WinMM names, which Windows may truncate to 31 UTF-16 units. Rename duplicate devices in Windows before selecting them. TTS accepts complete PCM16 mono/stereo WAV, 8–192 kHz, at most 32 MiB. Playback cancellation waits for the native helper to exit. Recognition queues at most four segments; overflow is reported in the panel. Process termination stops capture and requires another start.

Recognition uses SenseVoice at 16 kHz mono. The default energy threshold is −42 dBFS; language defaults to automatic detection. These are editable configuration values. Raw captured audio is held in memory for recognition and is not written by this World. Legacy `receiveViaDesktopPet` remains available as an interpretation hint for deployments that already wired desktop-pet input; process capture does not enable or alter that route.

The microphone plugin is a self-contained VST2-compatible DLL with no bundled third-party SDK. Its audio callback preserves input, mixes resampled speech and limits mixed peaks; named-pipe I/O runs off the audio thread. Each active processing instance receives its own copy. IPC is restricted to the configuring Windows user and audio-service identities. Builds are produced with `native/build-microphone.ps1` using a developer-provided compiler; the shipped DLL is used at runtime. Equalizer APO modes bypassed by an application or an unsupported device require the explicit output-device route.
