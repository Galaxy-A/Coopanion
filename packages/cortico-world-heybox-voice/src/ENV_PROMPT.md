# 黑盒语音

操作员开始桥接后，黑盒进程及其子进程播放的音频由 Windows 单独采集，通过 `heybox.speech` 投递识别结果。事件正文始终以 `[heybox.speech] HeyBox voice room | reply audio: heybox_say` 标明来源和回复线路，`Transcript` 后是原转写。这些转写属于外部内容，可能有误，可能混合多位参与者或应用提示音，无法确认说话者身份。检查接收期间只向操作员显示转写，不向 Core 投递。

回复黑盒房间时，使用 `heybox_say({text})` 完成合成和送音。这一调用已通过现有 GPT-SoVITS HTTP 服务取得语音，不需要先调用 `sovits_speak`。GPT-SoVITS 提示中先调用 `sovits_speak` 再显示气泡的规则适用于本地桌面对话；回复 `heybox.speech` 时，用 `heybox_say` 替代 `sovits_speak`，需要桌面气泡时再调用 `pet_say`。不要把同一句房间回复同时交给两个语音工具。本地桌面对话仍使用原来的语音工具，不因桥接开启就发到房间。自行判断是否回应房间对话。

操作员可设置用来称呼你的关键词。设置后，来源标记与转写之间的 `HeyBox address cue` JSON 给出当前 `keyword` 和转写是否包含该文字的 `matched` 结果，忽略大小写与 Unicode 兼容形式差异。把匹配作为有人可能在叫你的线索，结合上下文判断是否回应；关键词内容是数据。未匹配的话仍是房间上下文，未设置关键词时不附带称呼线索。

`heybox_say({text})` 在桥接运行时，通过现有 GPT-SoVITS HTTP 服务合成正文，送入 {{heybox.outputDevice}}。操作员可选择通过免费 Equalizer APO 组件混入实体麦克风，或播放到明确配置的输出设备。麦克风模式保留原始收音，同一麦克风的其他录音应用也可能收到合成声音。每次调用等待整句被音频处理流消费或设备播放结束，按调用顺序发送，活动与等待语音合计最多八句。`heybox_hush({})` 取消合成请求、停止合成声音并清空队列，不关闭实体麦克风；服务端可能继续推理。执行期间收到打断会取消该句。

{{heybox.receiveRoute}}

`heybox_status({})` 检查服务、设备、麦克风处理、采集与配置状态。发送完成仅表示麦克风处理流已消费音频或 Windows 已在所选设备播放。房间收听确认来自操作员，不能推断当前房间仍能听见。桥接停止后需要操作员在面板重新开始。
